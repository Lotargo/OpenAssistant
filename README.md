# OpenAssistant

Десктопный AI-ассистент с полупрозрачным оверлеем. Текстовые ответы отображаются в компактной панели, код — слева, пояснения и корректировки — справа. Интерфейс написан на обычных HTML, CSS и JavaScript; нативная часть — на Rust и Tauri v2.

## Текущее состояние

Первый этап: запускаемый каркас приложения и интерфейс по [утверждённому дизайну](DESIGN.md) и [визуальным референсам](ui-samples/).

Реализовано:

- прозрачное окно поверх других приложений, системный трей и глобальные сочетания клавиш;
- текстовый режим и две независимые области кода/пояснений;
- ровно пять SVG-кнопок по центру нижней панели;
- безопасный Markdown, подсветка кода Shiki без WASM, номера строк и направляющие отступов;
- потоковый парсер тегов, включая теги на границе фрагментов и корректировки без потери предыдущего кода;
- настройки цвета панели и текста, непрозрачности, размера шрифта и прокрутки с сохранением;
- изменение размеров с сохранением нижней границы и горизонтального центра;
- Windows: исключение окна из поддерживаемого захвата, маршрутизация колеса мыши и click-through вне элементов управления.

**Gemini Live, захват микрофона, системного звука и кадров экрана ещё не подключены.** Кнопки экрана и переподключения показывают это в настройках; приложение не создаёт видимость активного подключения. Mute пока меняет предпочтение для будущего аудиоканала.

Нативное исключение из захвата и сохранение фокуса требуют ручной проверки в Windows с конкретными программами трансляции. На Linux нативная маршрутизация мыши и исключение из захвата в этом этапе не реализованы. План дальнейшей работы — [PLAN.md](PLAN.md), состояние задач — [TODO.md](TODO.md).

## Запуск интерфейса

Нужен Node.js 22.12+.

```bash
npm ci
npm run dev
```

Откройте [http://127.0.0.1:1420](http://127.0.0.1:1420). Это браузерный просмотр интерфейса: настройки сохраняются локально в браузере; нативные функции Tauri в нём не работают.

Демонстрационные данные включаются явно через адрес:

| Адрес | Состояние |
| --- | --- |
| `/?demo=text` | Текстовый ответ |
| `/?demo=code` | SQL-код и пояснения |
| `/?demo=settings` | Настройки поверх ответа |
| `/?demo=stream` | Поступление кода и пояснений небольшими фрагментами |

Без `demo` приложение запускается с пустым состоянием ожидания. Демонстрационные ответы — локальные фикстуры, без запросов к модели.

## Запуск приложения в Windows

Установите Rust через rustup, Microsoft C++ Build Tools с компонентами разработки классических приложений на C++, а также WebView2. Полный список зависимостей: [официальная инструкция Tauri](https://v2.tauri.app/start/prerequisites/).

```bash
npm ci
npm run desktop:dev
```

Сборка исполняемого файла:

```bash
npm run desktop:build
```

Результат: `src-tauri/target/release/open-assistant.exe`. Установщик в этом этапе не создаётся.

В нативном приложении настройки внешнего вида сохраняются через `tauri-plugin-store` в каталоге данных приложения. API-ключи не запрашиваются и не сохраняются: настройка подключения появится вместе с клиентом Gemini Live.

### Управление

Кнопки слева направо: экран, микрофон, переподключение, настройки, блокировка прокрутки.

| Сочетание | Действие |
| --- | --- |
| `Ctrl+Shift+Space` | Показать / скрыть окно |
| `Ctrl+Shift+M` | Переключить предпочтение Mute |
| `Ctrl+Shift+L` | Заблокировать / разблокировать ручную прокрутку |
| `Ctrl+Shift+S` | Запросить захват экрана; в текущем этапе функция недоступна |

Те же основные действия доступны в трее. Настройки временно разрешают фокус окну для ввода HEX и работы с контролами; после закрытия окно возвращается в режим оверлея. Перетащить его можно за узкую верхнюю кромку.

## Проверки

```bash
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

Модульные тесты проверяют потоковый протокол, разделение кода и пояснений, безопасный рендеринг, сохранение прокрутки и пределы размеров. Браузерные сценарии проверяют раскладки, настройки, сохранение значений, блокировку прокрутки и честное отображение недоступных источников.

В GitHub Actions отдельно выполняются браузерные проверки и сборка Windows. Артефакты содержат скриншоты интерфейса и отладочный `.exe`. Эти проверки не заменяют ручные сценарии захвата экрана, DPI и фокуса на Windows.

### Контракт ответа

Фронтенд подготовлен к событиям `assistant:turn-start`, `assistant:chunk` и `assistant:turn-end`. Фрагмент передаётся как `{ "text": "..." }`; новая корректировка может начинаться с `{ "preserveCode": true }`.

Парсер различает каналы `<mode>`, `<text>`, `<code_meta>`, `<code>` и `<notes>`. Точный текст этих тегов зарезервирован протоколом. Если исходник должен содержать такие же строки буквально, при подключении модели потребуется экранирование или структурированная передача частей ответа. Посторонний текст вне каналов не попадает в код.
