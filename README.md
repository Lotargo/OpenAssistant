# OpenAssistant

Десктопный ассистент на Rust + Tauri v2 с полупрозрачным оверлеем, голосовым вводом и агентом Codex. Код, команды, поиск и инструменты выполняет установленный Codex через `app-server`; вход — через аккаунт ChatGPT в Codex. Полей для API-ключей и подключений сторонних провайдеров нет.

## Что работает

- Текстовые задачи Codex: чтение и изменение файлов выбранного проекта, команды, доступные Codex инструменты и веб-поиск.
- Потоковые ответы: Markdown в текстовом режиме, код слева и пояснения справа, безопасный HTML и подсветка Shiki.
- Живой каталог установленного Codex до подключения: модель, поддерживаемые уровни рассуждения и их значения по умолчанию.
- Выбор существующего проекта через системный диалог либо пустой временной рабочей папки с очисткой.
- Отдельные несохраняемые диалоги OpenAssistant; настройки уведомлений отключаются только в его дочернем процессе Codex.
- До трёх одновременных задач, журнал действий, переключение между результатами и отмена.
- Запросы разрешений и уточняющие вопросы Codex в настройках. Ответ передаётся в исходную сессию; приложение не подтверждает действия автоматически.
- Голосовой канал OpenAI Realtime через авторизацию Codex: непрерывный микрофон, ответ после паузы, транскрипция и передача поручений агенту.
- Нативное обнаружение микрофонов Windows, сохранение выбранного устройства и смена источника во время активной сессии.
- Локальная проверка микрофона, волна и уровень входящего сигнала, отдельное отображение перегрузки.
- Необязательное шумоподавление RNNoise; по умолчанию оно выключено.
- Сценарий собеседования: независимые микрофон и Windows loopback, семантический выбор момента для подсказки и отдельные задачи Codex с доступом только для чтения.
- Локальная анонимная группировка голосов участников встречи через Vosk; короткие и неоднозначные реплики остаются без номера.
- Настройки оформления, прозрачный оверлей, системный трей, горячие клавиши, независимая прокрутка и сохранение геометрии.

Микрофон и соединение с моделью запускаются по действию пользователя. Если голосовой канал недоступен, текстовые задачи Codex продолжают работать.

**Передача изображения экрана модели пока не реализована.** Соответствующий элемент показывает недоступность. Системный звук работает в сценарии собеседования через выбранное устройство вывода Windows. В режиме оверлея на Windows используется системное исключение окна из поддерживаемых способов захвата. В обычном оконном режиме OpenAssistant виден в скриншотах и трансляциях.

## Авторизация

1. Установите Codex CLI и войдите в него через ChatGPT:
   ```powershell
   codex login
   ```
2. Откройте OpenAssistant → настройки → **Агент**.
3. Выберите временную папку либо существующий проект, модель и уровень рассуждения. Каталог Codex загружается независимо от сессии; кнопка обновления запрашивает его заново.
4. Введите задачу либо включите микрофон на нижней панели.

Приложение запускает нативный бинарник Codex без shell-обёртки и проверяет, что активен ChatGPT-аккаунт. Провайдер агентной сессии — OpenAI. Переменные `OPENAI_API_KEY` и `CODEX_API_KEY` не передаются дочернему процессу.

Голосовой адаптер использует OAuth Codex для получения короткоживущего секрета Realtime. Учётные данные читаются только внутри Rust; они не отправляются в WebView, не сохраняются в настройках приложения и не включаются в диагностические сообщения. Доступность Realtime определяется ответом сервиса для текущего аккаунта. При отказе остаётся доступен текстовый Codex.

Текстовый агент использует механизм авторизации самого Codex. Для Realtime нужен доступный локальный OAuth credential store Codex; если его формат или доступность изменятся, ошибка отображается в настройках голосового канала.

## Запуск в Windows

Нужны Node.js 22.12+, Rust, Microsoft C++ Build Tools и WebView2.

```powershell
npm ci
npm run desktop:dev
```

Сборка:

```powershell
npm run desktop:build
```

Результат: `src-tauri/target/release/open-assistant.exe`. Установщик не создаётся.

Для запуска собранного приложения из корня проекта:

```powershell
.\src-tauri\target\release\open-assistant.exe
```

Настройки сохраняются через `tauri-plugin-store` в каталоге данных приложения. Настройки агента, микрофона и оформления отделены от учётных данных Codex.

## Управление

На нижней панели шесть кнопок: экран, микрофон, переподключение, настройки, блокировка прокрутки и режим окна. Задачи, модель, разрешения и журнал находятся внутри настроек; дополнительных панелей управления поверх ответа нет. До первого ответа панель остаётся пустой, без стартовой надписи.

| Сочетание | Действие |
| --- | --- |
| `Ctrl+Shift+Space` | Показать / скрыть окно |
| `Ctrl+Shift+M` | Включить / выключить микрофон |
| `Ctrl+Shift+L` | Заблокировать / разблокировать ручную прокрутку |
| `Ctrl+Shift+S` | Показать сообщение о недоступном захвате экрана |

Переподключение завершает текущую сессию. Отдельную задачу можно отменить на вкладке агента. При выходе из приложения закрываются голосовой канал и запущенный им процесс Codex.

## Агент и рабочая область

В **Настройки → Агент** модель и глубина рассуждений приходят из `model/list` установленного Codex. Список не зашит в приложение. Недоступный сохранённый выбор показывается явно; приложение не подменяет его другой моделью. Получение каталога не создаёт диалог или задачу и не включает микрофон.

- **Временная папка** — новая пустая область для текущего подключения. Подходит для SQL-примеров, коротких функций и экспериментов. При отключении, переподключении или выходе сначала завершается Codex, затем удаляется эта папка. После аварийного выхода оставшиеся папки проверяются при следующем запуске. Кнопка очистки доступна после завершения задач и прослушивания.
- **Папка проекта** — выбранный существующий каталог. Его содержимое сохраняется. Временная очистка никогда не удаляет пользовательские проекты; сохранённый путь можно переключать обратно без повторного выбора.

Очистка ограничена каталогами OpenAssistant с его маркером владения и блокировкой. Активные папки и ссылки Windows не обходятся рекурсивно. Если файлы ещё заняты, статус показывает отложенную очистку.

Каждый диалог OpenAssistant создаётся как `ephemeral`; приложение не продолжает открытый диалог Codex. Параметры `notify=[]` и `tui.notifications=false` действуют только на дочерний процесс. Глобальная конфигурация и пользовательские диалоги Codex не меняются.

## Собеседование и звук встречи

1. Во вкладке **Источники** выберите свой микрофон и устройство вывода, через которое слышна встреча.
2. Во вкладке **Агент** выберите **Собеседование**, модель Codex и рабочую область.
3. Нажмите **Начать прослушивание**. В этом сценарии кнопка микрофона на панели и `Ctrl+Shift+M` включают или останавливают оба источника.
4. Состояния **Слушаю**, **Определяю, нужна ли подсказка** и **Готовлю подсказку** показывают фактический этап. **Остановить** прекращает прослушивание; текстовые задачи Codex остаются доступны.

Windows loopback принимает всю смесь выбранного устройства вывода: Meet/Телемост в браузере, отдельное приложение и другой звук на том же устройстве. Это не захват конкретной вкладки. При цифровой тишине канал сохраняет корректный нулевой аудиопоток, чтобы детектор речи мог завершить последнюю реплику.

Микрофон и встреча передаются раздельно, с источником у каждой транскрипции. В этом режиме левая волна на панели показывает микрофон, правая — встречу. Автоматические ответы после каждой паузы выключены. Отдельная проверка контекста решает, нужен ли ответ пользователю: вопрос, просьба показать или объяснить функцию, SQL-задание либо явное «подскажи». Приветствия, организационные реплики, собственный ответ пользователя и вопрос другому участнику должны оставаться без подсказки. Неуверенное решение означает продолжение прослушивания.

Подсказка выполняется в отдельном несохраняемом Codex-диалоге с режимом только для чтения и возвращается текстом/кодом в панель. Она не получает разрешение менять выбранный проект из речи собеседника. Обычное поле задачи сохраняет самостоятельный режим работы агента.

### Различение голосов

Локальная Vosk-модель сравнивает голосовые признаки и назначает анонимные номера **Участник 1**, **Участник 2**. Это вероятностная группировка, не установление личности. Для уверенного сравнения требуется примерно четыре секунды чистой речи; короткие, неоднозначные и известные наложения голосов остаются неопределёнными. Наложение нескольких голосов внутри уже смешанного аудио не определяется надёжно. Наушники помогают отделить звук встречи от микрофона.

Профили голосов, недавний контекст и ограниченный аудиобуфер существуют в памяти текущего прослушивания. Аудиофайлы и база голосов на диск не записываются. Остановка очищает эти данные. При недоступной локальной модели источники «Мой микрофон» / «Звук встречи» остаются раздельными, а статус сообщает об отсутствии группировки.

Подготовка локальной модели из ресурсов `voice-input`:

```powershell
powershell -File .\scripts\prepare-speakers.ps1 -SourceResources 'F:\projects\voice-input\src-tauri\resources'
```

Скрипт копирует необходимые локальные Vosk-активы и получает официальную speaker-модель с проверкой SHA-256. Активы, лицензии и происхождение сохраняются в `%LOCALAPPDATA%\OpenAssistant\models\vosk-speakers`; бинарники не добавляются в Git. Справка: [модели Vosk](https://alphacephei.com/vosk/models), [пример сравнения голосов](https://github.com/alphacep/vosk-api/blob/master/python/example/test_speaker.py).

## Режим окна и перемещение

Кнопка **режима окна** переключает два варианта поведения:

| Режим | Поведение |
| --- | --- |
| Оверлей | Поверх других окон, скрыт из поддерживаемого захвата экрана и панели задач; сохраняет прежний режим взаимодействия с окнами под ответом |
| Обычное окно | Видно в захвате экрана и на панели задач, получает фокус, другие окна могут перекрывать его |

Выбор сохраняется после перезапуска. Оформление панели остаётся одинаковым в обоих режимах.

Чтобы переместить основное окно, зажмите левую кнопку мыши на свободном фоне, верхней области или свободной части нижней панели и потяните. Настройки перемещаются за заголовок. Настройки открываются в отдельном непрозрачном окне и перемещаются независимо: основная панель сохраняет размер и положение при их открытии, перемещении и закрытии. Кнопки, поля, ссылки, текст, код и полосы прокрутки не запускают перетаскивание.

## Микрофон и проверка звука

В **Настройки → Источники** выберите микрофон и нажмите **Проверить микрофон**. Проверка длится до 20 секунд и работает без подключения к Codex или Realtime. Она показывает волну и уровень сигнала; звук не сохраняется и не передаётся модели. Проверка останавливается при уходе с этой вкладки, закрытии или скрытии настроек и потере фокуса окна.

Для диктовки включите микрофон на нижней панели или нажмите `Ctrl+Shift+M`. Небольшой индикатор у этой кнопки и две волны в свободных областях слева и справа от кнопок реагируют на один и тот же входящий сигнал. Волны гаснут при выключении микрофона, тишине или устаревании данных; отдельный захват для них не запускается. Обычная диктовка продолжает работать при переключении в другое приложение.

Устройства перечисляются через нативный аудиослой Windows, поэтому список не зависит от разрешений WebView. Пункт **Системный** следует за устройством Windows по умолчанию. Если явно выбранный микрофон отключён, приложение сообщает об этом и не подменяет его другим источником. Кнопка обновления повторно получает список устройств.

Переключатель **Шумоподавление** включает локальный RNNoise и фильтр низкочастотного шума. Исходный уровень и перегрузка оцениваются до фильтрации, поэтому шумоподавление не скрывает слишком громкий вход. Выбор устройства и шумоподавления сохраняется после перезапуска.

Окно настроек имеет скруглённые углы и непрозрачный фон. На вкладке «Внешний вид» один HEX/HSV-редактор отдельно задаёт цвет панели, текста и акцента. Акцент применяется к активным вкладкам, фокусу и контролам и сохраняется вместе с оформлением. Окно сохраняет размер и положение между вкладками; длинное содержимое прокручивается внутри. Между окнами синхронизируются параметры, задачи Codex и уровни микрофона. Подключением к Codex и захватом звука управляет только основная панель.

```powershell
npm run dev
```

Откройте [http://127.0.0.1:1420](http://127.0.0.1:1420). Браузерный просмотр предназначен для дизайна и тестирования раскладок; подключение Codex и нативные функции доступны в приложении Tauri.

| Адрес | Состояние |
| --- | --- |
| `/?demo=text` | Текстовый ответ |
| `/?demo=code` | SQL-код и пояснения |

Демонстрационные данные — локальные фикстуры, без запросов к модели.

## Архитектура

| Путь | Назначение |
| --- | --- |
| `crates/assistant-core/src/auth.rs`, `provider.rs` | OAuth и подключение Realtime |
| `crates/assistant-core/src/codex.rs` | JSON-RPC транспорта Codex app-server через stdio |
| `crates/assistant-core/src/agent.rs` | Задачи, события, подтверждения, вопросы и отмена |
| `crates/assistant-core/src/bridge.rs`, `session.rs` | Голосовой протокол и общий жизненный цикл сессии |
| `crates/assistant-core/src/workspace.rs` | Владение временными папками, блокировки и безопасная очистка |
| `crates/assistant-core/src/interview.rs`, `interview_session.rs` | Раздельные источники, ограниченный контекст, проверка необходимости подсказки |
| `crates/assistant-core/src/interview_audio.rs`, `interview_speakers.rs`, `speakers.rs` | Буфер PCM в памяти, привязка реплик ко времени аудио и локальные анонимные группы голосов |
| `src-tauri/src/assistant.rs` | Tauri IPC, ограниченные очереди, изоляция сессий и завершение |
| `src-tauri/src/window_stealth.rs` | Режим окна, фокус, перетаскивание, размеры, исключение из захвата и Windows wheel hook |
| `src/js/session-transport.js`, `bridge.js` | Native Channel, настройки и состояние интерфейса |
| `src-tauri/src/audio.rs`, `audio/` | CPAL/WASAPI, устройства, захват, локальный шумодав, ресемплинг и уровни |
| `src-tauri/src/audio_commands.rs` | Нативные команды обнаружения, запуска и остановки микрофона |
| `src/js/microphone.js`, `native-microphone.js`, `system-audio.js` | Независимые устройства, локальная проверка и передача PCM 24 кГц с меткой источника |
| `src/js/microphone-meter.js` | Волна и индикаторы звука без перерисовки настроек |
| `src/js/markdown-stream.js`, `renderer.js` | Потоковый Markdown, разделение кода и пояснений |
| `src/js/settings-modal.js`, `settings-window.js` | Форма настроек в отдельном системном окне, задачи и диалоги разрешений |
| `src/js/settings-window-bridge.js` | Синхронизация двух окон без повторного подключения Codex или микрофона |

Ядро не зависит от HTTP-сервера и интерфейса. Между Rust и WebView проходят только команды, аудиофрагменты и безопасные события. Локальный порт для работы приложения не открывается. Устаревшие события и команды прошлой сессии не могут изменять новую.

## Проверки

```powershell
npm test
npm run build
npm run test:e2e
cargo test --manifest-path crates/assistant-core/Cargo.toml
cargo test --manifest-path src-tauri/Cargo.toml
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
```

Браузерные тесты используют управляемый Tauri IPC mock и не обращаются к моделям. Rust-тесты проверяют протокол, валидацию, авторизацию, ограничения очередей, отмену и работу дочернего mock app-server. Проверки настоящего Codex и Realtime запускаются отдельно и не входят в обычный тестовый прогон.

GitHub Actions отключены. Проверки и сборка выполняются локально.
