### 1. Концепция и стратегия по модели

* **Стек:** Rust + Tauri v2 (бэкенд, окна, хуки, аудио, захват экрана, WebSocket) + чистый Vanilla JS / CSS / HTML (интерфейс).
* **Единая модель:** `gemini-robotics-er-2-streaming-preview` через WebSocket Live API (`BidiGenerateContent`).
  * Принимает сырой аудиопоток (`PCM 16-bit, 16 kHz, mono`), видеокадры (`image/jpeg`, ≤ 1 FPS) и текст.
  * Нативно возвращает потоковый ответ сразу в тексте (`responseModalities: ["TEXT"]`), без генерации лишнего аудио.
  * В `setup`-сообщении сразу включаются `contextWindowCompression` (`slidingWindow`) и `sessionResumption` + обработка серверного события `GoAway`, чтобы обходить ограничения времени live-сессии и переподключаться с сохранением контекста (плюс ручная кнопка `Reconnect` в UI).
* **Никаких других моделей и адаптеров:** для собеседований и простого лайв-кодинга возможностей базовой модели более чем достаточно. Сложные рабочие задачи решаются не переключением LLM-провайдеров в коде, а через локальные CLI-инструменты во втором этапе.

### 2. Двухэтапное развитие логики агента

#### Этап 1 (MVP — без Tool Calling)
* В `setup` передаётся только `systemInstruction`, без `tools` / `functionDeclarations`.
* Агент работает максимально быстро в режиме «слушатель + зритель + суфлёр»:
  * слышит собеседника и пользователя, различая роли;
  * на теоретические вопросы даёт краткий текстовый ответ;
  * на простые задания по лайв-кодингу (SQL-запрос, базовый скрипт, функция) сразу пишет чистый код с указанием, какой файл и с каким расширением создать (например, `query.sql` или `main.py`);
  * при активной демонстрации экрана корректирует действия пользователя по мере ввода кода.

#### Этап 2 (Рабочий режим — делегирование в `codex` / `agy` через CLI)
* В `setup` добавляется **один универсальный инструмент** (например, `run_cli_agent`), а в настройках появляется выбор рабочей директории проекта (`workspace_dir`).
* Никаких адаптеров под разные нейросети писать не нужно: на стороне Rust реализуется единый безопасный исполнитель локальных команд (через `tokio::process::Command` с таймаутом и захватом `stdout`/`stderr`), а **вся логика выбора инструмента и формирования аргументов задаётся в `systemInstruction`**:
  * Если на мите/в работе нужно изучить файлы локального репозитория, проверить архитектуру или решить сложную задачу, агент сам формирует вызов `codex` или `agy` в рабочей папке, получает результат через `toolResponse` и выводит готовую выжимку/код в UI.
  * Для безопасности на уровне Rust можно добавить простой белый список бинарников (`codex`, `agy` и опционально `git`/`rg` только на чтение) и иконку-индикатор выполнения CLI-команды в UI.

### 3. Захват звука и разделение ролей

Вне зависимости от того, открыт ли созвон в браузере (Яндекс Телемост, Google Meet) или в отдельном приложении (Zoom, Teams, Discord), приложение забирает два потока:

1. **Системный звук (Loopback — голос собеседника):**
   * **Windows:** `cpal` (WASAPI Loopback) + ресемплер `rubato` в `16 kHz mono s16le` через lock-free буфер `rtrb`.
   * **macOS:** `ScreenCaptureKit` (Audio Tap, без установки виртуальных аудиокабелей).
   * **Linux:** PipeWire / PulseAudio monitor source.
2. **Активный микрофон (голос пользователя):**
   * Захват через `cpal` → ресемплер в `16 kHz`.
   * Подавление эха (AEC через `webrtc-audio-processing` или программный ducking по RMS-сравнению с loopback), чтобы при работе без наушников звук из колонок не дублировался через микрофон.
   * Кнопка **Mute** в UI глушит только канал микрофона, не затрагивая прослушивание собеседника.

#### Разделение ролей в диалоге:
* **Вариант А (оптимальный):** Loopback (собеседник) стримится напрямую в `realtimeInput.audio` (мгновенная реакция на вопрос рекрутера), а микрофон проходит локальный VAD (`webrtc-vad`) + лёгкую локальную транскрибацию (`whisper-rs` tiny/base) и отправляется в сессию как текст с префиксом `[Пользователь]: ...` (с `NO_INTERRUPTION`, если пользователь просто комментирует свои действия).
* **Вариант Б (ещё проще для самого старта):** общий VAD-мультиплексор в один аудиопоток, где Rust при смене активного канала шлёт короткий текстовый маркер смены говорящего (`[Говорит собеседник]` / `[Говорит пользователь]`).

### 4. Захват экрана и строгий формат вывода ответа

#### Захват экрана
* По кнопке в UI запускается поток на базе `xcap` (≤ 1 кадр/сек, ресайз до ~1280px по ширине, JPEG ~70–75%).
* Перед отправкой в `realtimeInput.video` проверяется разница с предыдущим кадром (frame diff) — статичный экран не спамит токенами.
* Поскольку окно самого ассистента скрыто от системного захвата (`WDA_EXCLUDEFROMCAPTURE`), агент видит **чистый экран пользователя** без собственных подсказок поверх IDE.

#### Потоковый протокол вывода (`<mode>` / `<text>` / `<code>` / `<notes>`)
Чтобы в **левое поле кода не просочилось ни одного слова из пояснений**, модель через `systemInstruction` обязуется оборачивать ответ в строгие теги, которые парсер на фронтенде разбирает на лету символ за символом:

* **Режим текста (`<mode>text</mode>`):**
  * Заполняется только верхнее поле `TEXT`. Окно остаётся компактным и растягивается по вертикали ровно под объём текста.
* **Режим кода (`<mode>code</mode>`):**
  * Прямоугольник плавно расширяется и открывает нижнюю двухколоночную область (строго по твоему макету):
    * `<code_meta>{"filename":"query.sql","lang":"sql"}</code_meta>` — имя и расширение файла (чтобы новичок точно знал, какой файл создать в IDE).
    * `<code>...</code>` → **левая колонка**: чистый код с подсветкой, нумерацией строк и направляющими отступов.
    * `<notes>...</notes>` → **правая колонка**: пошаговые подсказки (как создать файл с нужным расширением, что делает код) и живые корректировки при захвате экрана (`<mode>correction</mode>`).

### 5. «Невидимость» UI, идеальная мышь и скролл

1. **Исключение из захвата экрана:**
   * `window.set_content_protected(true)` в Tauri v2 (`WDA_EXCLUDEFROMCAPTURE` на Windows 10/11, `sharingType = .none` на macOS).
   * *Важная страховка от бага Tauri v2 (#14189):* при любом переключении видимости окна на Windows повторно применять `set_content_protected(true)` (или скрывать прозрачностью/размером вместо `hide()/show()`), чтобы на шаринге не появлялся чёрный прямоугольник.
2. **Невидимость поведения курсора для наблюдающего:**
   * Окно всегда работает в режиме `alwaysOnTop: true`, `focusable: false` (`WS_EX_NOACTIVATE` на Windows) и **`set_ignore_cursor_events(true)`**.
   * При наведении мыши на область текстового или кодового блока курсор не меняет иконку (например, остаётся I-beam в IDE), hover-эффекты под оверлеем не срываются, а клики не забирают фокус у IDE/браузера. У зрителя на демонстрации не возникает никаких подозрений.
3. **Прокрутка блоков без выхода из `click-through`:**
   * В Rust запускается низкоуровневый хук только на колесо мыши (`SetWindowsHookExW(WH_MOUSE_LL)` для `WM_MOUSEWHEEL` на Windows / `CGEventTap` на macOS). `WM_MOUSEMOVE` не перехватывается.
   * Фронтенд передаёт в Rust координаты панелей (`text`, `code`, `notes`).
   * Если **Scroll Lock выключен** и курсор находится над одной из панелей оверлея → хук **поглощает** прокрутку (IDE под окном остаётся на месте) и передаёт событие прокрутки в JS (`panel.scrollBy`).
   * Если **Scroll Lock включён** → хук пропускает событие колеса дальше в ОС.
4. **Нажатие на SVG-кнопки управления и модалка настроек:**
   * Небольшой трекер координат курсора (раз в ~20 мс) временно включает `set_ignore_cursor_events(false)` **только** когда курсор попадает на узкую полоску с SVG-кнопками или в открытую модалку настроек (окно при этом остаётся неактивируемым, не забирая фокус у IDE). При уходе курсора на текстовое/кодовое поле или за границы окна — мгновенно возвращается `click-through`.
   * Критические действия (шаринг, Mute, Scroll Lock, скрыть/показать) дублируются глобальными хоткеями (`tauri-plugin-global-shortcut`).

### 6. Дизайн UI, прозрачность, настройки и JS-библиотеки

#### Внешний вид и прозрачность (Tauri v2 + CSS)
* Конфиг окна: `"decorations": false`, `"transparent": true`, **`"shadow": false`** (без `shadow: false` в Tauri v2 на Windows ломаются прозрачность и углы).
* Фон делается чистым CSS `rgba(R, G, B, alpha)` без системных эффектов размытия (`acrylic`/`backdrop-filter`), так как они конфликтуют со скруглениями `border-radius: 14px` и вызывают лаги при динамическом ресайзе.
* По умолчанию: тёмный графит `#202226` с прозрачностью **50%** (`rgba(32, 34, 38, 0.5)`), белый текст `#FFFFFF`.
* **В основном UI — только SVG-кнопки (без подписей):**
  1. Захват экрана (с индикацией активности).
  2. Заглушить микрофон (Mute).
  3. Переподключение (Reconnect + цветной статус сокета).
  4. Блокировка скролла (Scroll Lock).
  5. Настройки (Шестерёнка).
  *(Плюс область перетаскивания `data-tauri-drag-region` в верхней рамке).*
* **Авто-ресайз:** `ResizeObserver` следит за блоком `TEXT` и при изменении объёма текста плавно подгоняет высоту окна (`setSize`) вплоть до заданного максимума (~65% высоты экрана), после чего включается внутренний скролл.

#### Модалка настроек (по макету №2)
* Открывается по шестерёнке (с временным увеличением окна под габариты модалки и возвратом к размеру контента при закрытии, либо в отдельном защищённом окне с живым превью через IPC).
* Внутри модалки (тут все элементы с текстовыми подписями):
  * **HEX-палитра (кастомный компонент на `<canvas>` + Vanilla JS):** 2D-квадрат Saturation/Value, шкала Hue, ввод HEX/RGB/HSL — отдельно для **цвета панели** и **цвета шрифта**.
  * **Прозрачность панели:** слайдер `10% – 100%`.
  * **Размер шрифта:** слайдер `12px – 22px`.
  * **Аудио и API:** API-ключ Gemini, выбор микрофона и устройства вывода (loopback), переключатель режима разделения ролей.
  * *(Во 2-м этапе: путь к рабочей папке и разрешение на запуск CLI `codex`/`agy`).*
* Сохранение конфигурации через `tauri-plugin-store`.

#### Библиотеки для чистого JS/CSS/HTML
* **Подсветка кода (уровень IDE со скриншота №3):**
  * **Основной выбор: `Shiki`** (`@shikijs/core` + `createJavaScriptRegexEngine()` без WASM + популярные языки `sql`, `python`, `js/ts`, `bash`, `go`, `rust`, `java`, `cpp`, `json`, `html`, `css` + тема `dark-plus` / `one-dark-pro`). Shiki оборачивает каждую строку в `<span class="line">`, поэтому колонка номеров строк и вертикальные направляющие отступов делаются элементарно на CSS. При стриминге подсветка троттлится раз в `60–80 мс` через `requestAnimationFrame`. *(Сборка фронта в `dist/` минимальным `esbuild`/`vite`, сам код полностью на Vanilla JS).*
  * **Альтернатива (вообще без npm/сборщика):** локальные скрипты `highlight.js` + `highlightjs-line-numbers.js` (подключаются напрямую тегом `<script>`, чуть проще грамматика, но ноль сборочных шагов).
* **Markdown и защита:** `marked` + `DOMPurify` (для блоков `TEXT` и `NOTES`).

### 8. Пошаговый план реализации (Roadmap)

**Фаза 1 (MVP — Ассистент для собеседований и митов):**
1. **Каркас окна и стелс:** Tauri v2 с прозрачностью и скруглениями (`shadow: false`), `set_content_protected(true)`, `click-through` + `WS_EX_NOACTIVATE`, тест на захвате экрана (Zoom/Телемост/OBS).
2. **Идеальный скролл и тулбар:** трекер ховера только на полоске SVG-кнопок + хук колеса мыши с учётом кнопки Scroll Lock + динамический авто-ресайз высоты.
3. **Аудио + WebSocket Gemini Live:** захват Loopback и микрофона (16 kHz PCM), разделение ролей, подключение к `gemini-robotics-er-2-streaming-preview` (`TEXT`, `contextWindowCompression`, `sessionResumption`), кнопка Reconnect и Mute.
4. **Экран + IDE-вывод:** кнопка шаринга экрана (`xcap` + JPEG diff), потоковый парсер тегов, подсветка кода (Shiki / Highlight.js) с шапкой файла и нумерацией строк, Markdown в `TEXT` и `NOTES`.
5. **Модалка настроек:** Canvas HEX-пикер, цвет шрифта, размер шрифта, прозрачность 0–100%, выбор аудиоустройств, сохранение настроек.

**Фаза 2 (Рабочий режим с локальными CLI):**
6. **CLI-мост и инструкции:** добавить в `src-tauri` модуль `cli_bridge.rs` и пробросить одно `functionDeclaration` в `setup` WebSocket-сессии. Расширить `systemInstruction` правилами вызова `codex` / `agy` для работы с локальным кодом и глубокого анализа. Добавить в настройки выбор рабочей папки и индикатор выполнения CLI-инструмента в тулбаре.
