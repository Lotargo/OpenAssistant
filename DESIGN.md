# Design Specification — Desktop AI Assistant Overlay

> Статус: утверждённое направление UI (тёмная редакция).  
> Платформа: Windows desktop · Tauri / Rust · HTML / CSS / JavaScript.  
> Назначение: контекстные текстовые и программные подсказки во время созвонов, собеседований, live coding и рабочих встреч.

## 1. Концепция

Приложение — минималистичный полупрозрачный оверлей поверх открытых окон. Ассистент воспринимает аудио собеседников, аудио микрофона и, по разрешению пользователя, изображение экрана. Результат показывается в одном из двух режимов:

- **Text** — одно поле с отрендеренным Markdown для кратких ответов, пояснений и последовательности действий.
- **Code + Guidance** — расширенное окно с кодом слева и пояснениями справа.

Режим определяется типом ответа агента, а не переключается пользователем вручную. Интерфейс адаптируется к объёму содержимого без резких скачков положения.

**Ключевой принцип:** почти всё пространство принадлежит ответу, элементы управления сведены к одной центрированной нижней панели. Никакого верхнего тулбара, логотипа, точки активности или постоянных подписей у кнопок.

## 2. Визуальная система

| Параметр | Спецификация |
| --- | --- |
| Фон демонстрационного макета | Тёмно-серый / почти чёрный, без зелёного свечения, ярких градиентов и декора |
| Фон самого оверлея | `#202329` с начальной непрозрачностью **50%** (`rgba(32, 35, 41, 0.5)`) |
| Подложка кода | Более плотный графит `#171A20`, допускается небольшое отличие по прозрачности для читаемости |
| Основной текст | `#F5F7FA` |
| Вторичный текст | `#BAC0C9` |
| Границы | `1px solid rgba(255,255,255,0.14)` |
| Разделители | `1px solid rgba(255,255,255,0.10)` |
| Скругление внешней панели | `18–22px` |
| Скругление внутренних блоков | `12–14px` |
| Фоновые эффекты | Умеренный `backdrop-filter: blur(12px)` при наличии поддержки; без сильного glow |
| Тени | Мягкая тень `0 12px 40px rgba(0,0,0,0.30)` |
| Шрифт интерфейса | Segoe UI / Inter / системный sans-serif |
| Шрифт кода | Cascadia Code / JetBrains Mono / monospace |
| Основной текст | По умолчанию `15px`, line-height `1.5` |
| Код | По умолчанию `13–14px`, line-height `1.55` |
| Отступы | Сетка `8px`; содержимое `20–24px`, зазор между блоками `12–16px` |
| Акцент по умолчанию | Нейтральный светло-серый; цветные токены допускаются только для подсветки синтаксиса и состояний |

**Цвет панели и цвет текста настраиваются отдельно.** Выбор оттенка через HEX-палитру меняет именно панель, а не только цвет акцентной полоски. Начальная прозрачность — 50%; регулировка должна показывать, что меняется *непрозрачность* панели, чтобы не путать обратные шкалы.

Контент должен оставаться читаемым поверх светлого приложения: если системный blur недоступен, использовать более плотный локальный фон контентных блоков, не меняя сохранённый пользователем основной цвет панели.

## 3. Компоновка и состояния

### 3.1. Обычный режим — Text

```text
╭──────────────────────────────────────────────╮
│                                              │
│  Отрендеренный Markdown-ответ                 │
│  Заголовки, абзацы, списки, inline code       │
│                                         ▏    │
│                                              │
├──────────────────────────────────────────────┤
│             ◫   mic   ↻   ⚙   ♙              │
╰──────────────────────────────────────────────╯
```

- Единственная область контента без табов, боковых панелей и декоративных заголовков.
- Markdown отображается **как форматированный текст**, без сырой разметки `#`, `**` и обратных кавычек.
- Высота растёт вместе с ответом — от компактного состояния до заданного предела, после чего появляется внутренний скролл.
- Ширина в этом режиме постоянна в пределах адаптивного диапазона; изменение объёма текста не должно вызывать горизонтальных скачков.
- Нижняя полоса всегда прикреплена к низу панели и содержит пять кнопок по центру.

### 3.2. Режим Code + Guidance

```text
╭────────────────────────────────────────────────────────────────────╮
│  ┌─────────────────────────────────┐ ┌───────────────────────────┐ │
│  │ users.sql                       │ │ Что делать                │ │
│  ├─────────────────────────────────┤ │                           │ │
│  │  1  SELECT id, name             │ │ 1. Создайте users.sql     │ │
│  │  2  FROM users                  │ │ 2. Вставьте запрос        │ │
│  │  3  WHERE status = 'active';    │ │ 3. Запустите в SQL-клиенте│ │
│  │                            ▏   │ │                        ▏  │ │
│  └─────────────────────────────────┘ └───────────────────────────┘ │
├────────────────────────────────────────────────────────────────────┤
│                        ◫   mic   ↻   ⚙   ♙                         │
╰────────────────────────────────────────────────────────────────────╯
```

- **Слева** — read-only отображение кода в стиле IDE: моноширинный шрифт, номера строк, отступы, подсветка синтаксиса, отдельная вертикальная прокрутка.
- **Справа** — отрендеренный Markdown: название файла/расширения, порядок действий, пояснения и корректировки по увиденному экрану.
- Пропорция по умолчанию: **60% код / 40% пояснения**. При небольшом разрешении панель адаптируется с сохранением обоих блоков, а не смешивает код с инструкциями.
- Допускается строка с именем файла, например `users.sql`; это **название результата**, не дополнительная кнопка или вкладка управления.
- В код никогда не вставляются пояснительные абзацы из правого блока. В инструкциях допускается короткий inline code, но полноценный исходник остаётся слева.
- Скролл двух областей независим. Обновление одной области не сбрасывает позицию другой.
- При возврате к текстовому ответу лишняя колонка закрывается, окно плавно возвращается к обычной ширине.

### 3.3. Модальное окно настроек

Настройки открываются через иконку параметров в нижней панели. Это отдельный модальный слой по центру экрана. Основной оверлей за ним затемняется; при открытой модалке нижняя панель временно не принимает события.

По уточнению владельца проекта оформление настроек следует Antigravity Engine SDK: нейтральные поверхности `#18181b` / `#222225`, тонкая рамка `#343438`, компактные контролы и сдержанный тёплый акцент фокуса. Размер диалога — `860×690px` с ограничением по доступному экрану. Все вкладки сохраняют одни границы; прокрутка находится внутри содержимого. Исходные `ui-samples` остаются ориентиром для самого оверлея.

**Вкладка «Внешний вид»:**

| Контрол | Поведение |
| --- | --- |
| Цвет панели | Поле оттенка/насыщенности, полоса hue, образец и редактируемое значение `#RRGGBB` |
| Непрозрачность | Ползунок `0–100%`, начальное значение `50%`, числовое значение рядом |
| Цвет шрифта | Образец и HEX-поле, начальное значение `#F5F7FA` |
| Размер шрифта | Компактный контрол с предустановками или числовое значение в px |
| Предпросмотр | Изменения сразу видны на фоне в основном оверлее |

**Вкладка «Поведение»:** блокировка прокрутки, предел автоматического увеличения высоты, способ автопрокрутки при поступлении новых фрагментов.

**Вкладка «Источники»:** выбор микрофона, локальная проверка до 20 секунд, волна и уровень звука, перегрузка и необязательное шумоподавление. Системный звук и изображение отмечены недоступными до реализации. Проверка не передаёт звук модели и останавливается при уходе из источников, скрытии или потере фокуса настроек. У кнопки микрофона в основной панели допускается компактный индикатор входящего сигнала без отдельной кнопки или подписи.

Все текстовые названия кнопок, параметров и источников допустимы **только в настройках**. Основная панель остаётся без подписей и без всплывающих текстовых подсказок у иконок. Для доступности можно использовать невидимые `aria-label`.

## 4. Нижняя панель управления

Единственный постоянный набор элементов управления — **ровно пять SVG-иконок** в одной горизонтальной строке:

| Порядок | Иконка | Действие |
| --- | --- | --- |
| 1 | Монитор | Включить/отключить передачу изображения экрана **модели** |
| 2 | Микрофон | Выключить/включить захват локального микрофона для агента |
| 3 | Круговая стрелка | Переподключить поток модели при сбое |
| 4 | Параметры | Открыть настройки |
| 5 | Замок | Заблокировать/разблокировать ручную прокрутку блоков |

- Иконки — единый outline SVG-стиль с центром `12,12` в `viewBox 0 0 24 24`, размер визуального символа около `20px`, интерактивная зона не менее `36×36px`.
- Все пять кнопок центрированы **относительно всей панели**, с одинаковыми интервалами.
- Полоса управления высотой около `56px`, отделяется тонким горизонтальным разделителем.
- По умолчанию иконки светлые, без подложки каждой кнопки; hover — мягкое изменение прозрачности/фона без подписей и всплывающих панелей.
- Состояния показываются самой иконкой: микрофон перечёркнут при выключении; замок закрыт при блокировке; иконка экрана отличается по состоянию захвата. При переподключении допускается анимация самой стрелки.
- **Не добавлять:** логотип, индикатор «онлайн», название модели, текстовый статус, кнопку копирования, отдельную кнопку сворачивания, верхний toolbar или шестую кнопку.

## 5. Размеры, позиционирование и анимации

| Свойство | Text | Code + Guidance |
| --- | --- | --- |
| Ориентир ширины | `760–980px` | `1100–1400px` |
| Ограничение по экрану | `max-width: 90vw` | `max-width: 94vw` |
| Минимальная высота | Достаточна для 1–3 строк и нижней панели | Достаточна для нескольких строк кода и пояснения |
| Максимальная высота | `min(70vh, 760px)` | `min(75vh, 820px)` |
| Изменение размеров | Автоматическое по контенту с ограничением | Плавное расширение ширины и высоты |

- Основная точка привязки: **горизонтальный центр, фиксированное положение нижней границы**. При росте ответа окно увеличивается преимущественно **вверх**, чтобы нижние кнопки не «убегали» от курсора.
- Плавные переходы ширины и высоты около `160–220ms`, без пружинных эффектов.
- Для потокового ответа размер обновляется с небольшим batching/debounce, а не при каждой поступившей букве.
- При достижении максимальной высоты продолжение текста появляется внутри скроллируемой области, а внешняя геометрия остаётся неподвижной.
- Если пользователь вручную прокрутил текст вверх, новые токены не должны принудительно возвращать его в конец.

## 6. Поведение мыши, прокрутки и демонстрации экрана

1. **Нативный курсор:** приложение не меняет координаты мыши, не прячет и не подменяет системный указатель, не делает программных перемещений при наведении на оверлей.
2. **Колёсико над содержимым:** при отключённом scroll lock вращение колеса прокручивает блок, над которым расположен указатель. В split-режиме это две независимые области.
3. **Scroll lock:** при включении ручной скролл обоих блоков запрещён. События колеса не должны неожиданно менять положение текста. Порядок передачи колеса приложению под оверлеем требует отдельного тестирования на Windows.
4. **Области событий:** кнопки и полосы прокрутки интерактивны; за пределами реально видимой/интерактивной панели обработка мыши не нужна. Если используется click-through, он должен применяться только там, где не ломает колесо и управление.
5. **Захват изображения:** передача изображения экрана модели и демонстрация экрана другим участникам — разные процессы. Если требуется исключать оверлей из внешней трансляции, использовать поддерживаемые ОС механизмы исключения окна из захвата, но **не считать это гарантией** для всех приложений и способов трансляции; необходима проверка на реальных сценариях.
6. **Без скачков:** адаптация размеров не перехватывает системный курсор и не переставляет кнопки произвольным образом. Центр нижнего блока управления сохраняется при переходе Text ↔ Split.

## 7. Рендеринг ответов

### Markdown

- Поддержка заголовков, списков, полужирного/курсива, ссылок и inline code.
- Санитизация HTML; сырая разметка и скрипты от модели не выполняются.
- Никаких пузырей чата, аватаров, декоративных блоков «Assistant» и временных меток.
- Текст отображается потоково, при этом незавершённые Markdown-конструкции не должны ломать верстку.

### Код

- Подсветка для SQL, Python, JavaScript/TypeScript, Bash, Rust и других языков по типу блока или расширению файла.
- Только read-only просмотр; для отображения кода не требуется полноценная IDE с автодополнением и тяжёлым редактором.
- Номера строк, сохранённые пробелы/табуляция, горизонтальный скролл для длинных строк и независимый вертикальный скролл.
- Пояснения о создании файла (например, `users.sql`) и последовательности действий находятся справа.

## 8. Реализация и границы ответственности

| Слой | Ответственность |
| --- | --- |
| **Rust / Tauri** | Создание прозрачного always-on-top окна, управление размером и положением, нативный захват аудио/экрана, системные разрешения, lifecycle соединения |
| **HTML / CSS / JS** | Обе раскладки, футер с SVG-иконками, анимации, модалка и цветовая палитра |
| **Markdown renderer** | Безопасный рендеринг потокового Markdown |
| **Syntax highlighter** | Лёгкая подсветка read-only кода; предпочтительны решения без тяжёлого полнофункционального редактора |
| **State** | Текущий режим, массив файлов/фрагментов кода, Markdown-подсказки, положение скролла, тема, размер и непрозрачность |

Библиотеки подсветки и Markdown выбираются после проверки производительности в Tauri WebView. Визуальная спецификация не зависит от конкретного пакета.

## 9. Критерии приёмки UI

- [ ] В обычном режиме отображается **одно** поле с корректно отрендеренным Markdown.
- [ ] При появлении кода окно переходит в **две** колонки: код слева, инструкции справа.
- [ ] Содержимое левого блока имеет вид IDE: подсветка, номера строк и скролл.
- [ ] Количество постоянных кнопок — **ровно пять**, они центрированы **в нижней части** окна.
- [ ] Нет логотипа, общего индикатора онлайн, верхнего toolbar и текстовых подписей в основной панели; у микрофона допустим индикатор реального входящего звука.
- [ ] Дефолтный цвет — тёмный графит, непрозрачность — **50%**, текст белый; нет зелёного фонового свечения.
- [ ] В настройках меняются HEX-цвет панели, HEX-цвет текста, размер шрифта и непрозрачность.
- [ ] Окно увеличивается по вертикали до лимита, затем включается внутренняя прокрутка.
- [ ] Каждая половина split-режима прокручивается независимо; scroll lock работает предсказуемо.
- [ ] Изменение размеров и взаимодействие с UI не перемещают системный курсор.
- [ ] Проверено поведение прозрачного окна и видимости оверлея при захвате экрана в выбранных приложениях.

## Визуальные референсы

Утверждённые референсы пользовательского интерфейса находятся в директории `ui-samples/`:

- `01_text_mode.png` — стандартный режим отображения текста.
- `02_code_and_guidance.png` — разделённый режим отображения кода и пояснений.
- `03_settings_modal.png` — модальное окно настроек интерфейса.

**При проектировании каждого элемента UI обязательно сверяться с соответствующими референсами.**

Референсы являются основным визуальным ориентиром для компоновки, пропорций, цветовой палитры, прозрачности, скруглений, типографики, расположения элементов управления и оформления отдельных компонентов.

Все три состояния интерфейса должны сохранять единый визуальный стиль. Любые изменения дизайна должны соответствовать референсам и требованиям настоящего документа. Не допускается произвольное добавление элементов, изменение расположения кнопок или переосмысление утверждённого оформления.
